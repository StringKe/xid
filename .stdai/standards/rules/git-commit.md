# Git Commit Rules

## Message format

[Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/): `<type>(<scope>): <description>`

- Types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`.
- Breaking changes append `!` to the type: `feat(api)!: remove legacy endpoint`.
- Stage every file that belongs to the change. Never silently exclude one.
- Never commit `.env` files, secrets, real tenant identifiers, tokens, client secrets, or private
  keys. Tell the user instead of deciding for them. `pnpm run security:secret-scan` catches some of
  this; it is not a substitute for care.
- Never add `Co-Authored-By` trailers or any other AI attribution.

## DCO sign-off (mandatory)

Every commit MUST carry a `Signed-off-by` trailer matching the commit author (`git commit -s`).
Pull requests with unsigned commits are blocked.

DCO trailer mechanics, the single rebase exception, and the pre-pull-request command list: reference
`git-workflow-details`. Read it when a sign-off is missing, before rebasing anything, or before
opening a pull request.

## Never rewrite pushed history

- FAIL: `git commit --amend` plus `git push --force` / `--force-with-lease` on a pushed branch.
- FAIL: `git rebase` plus `git push --force` on a pushed branch.
- FAIL: `git reset --hard <older>` plus `git push --force` on a pushed branch.
- The only way to correct a pushed commit is a new commit plus a fast-forward push.
- `main` is never force-pushed, and nothing is pushed directly to `main`. Branch first.
- There is exactly one narrow exception, spelled out in reference `git-workflow-details`. If you have
  not read it, there is no exception.

## Committing generated AI configuration

Files generated by `stdagent sync` (`CLAUDE.md`, `AGENTS.md`, `.claude/`, `.agents/`) are tracked on
purpose: commit them alongside the source change, never edit one directly, never `.gitignore` one.

Why generated AI config is committed and never hand-edited: reference `stdagent-config-workflow`.

## DPoP Nonce Is Not Implemented

The DPoP nonce challenge (RFC9449 section 9: the server issues a DPoP-Nonce and requires the client to carry it) is not implemented. Current replay defense: one-time proof `jti` (Durable Object) plus a 60s `iat` window plus `ath` binding, which covers the main replay surface; the nonce is optional hardening. The `use_dpop_nonce` response path is reserved; implementing it requires storing a per-jkt nonce in a Durable Object, and that is deferred for later evaluation.

## Shared Signals Placeholder Boundary

Product decision: SSF, CAEP, and RISC are not supported. The route boundary returns an explicit protocol error and never creates a stream or claims a security event was delivered. Full transmitter lifecycle, delivery, and receiver verification are future work.

Schema placeholder for future work:

| Area                 | Placeholder boundary                                                                                                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SET JOSE header      | Future schema must require `typ=secevent+jwt` and an explicit signing algorithm allowlist.                                                                                                |
| SET claims           | Future schema must model `iss`, `jti`, `iat`, `aud`, optional `txn`, top-level `sub_id`, and `events`; `sub` and `exp` stay rejected for SSF SETs.                                        |
| Subject identifiers  | Future schema must support SSF `sub_id` formats before mapping CAEP or RISC event types to XID users, sessions, devices, applications, organizations, or groups.                          |
| Event namespaces     | Future schema must separate `https://schemas.openid.net/secevent/ssf/`, `https://schemas.openid.net/secevent/caep/`, and `https://schemas.openid.net/secevent/risc/` event type handling. |
| Delivery constraints | Future transmitter and receiver code must validate stream issuer, audience, signing key, delivery method, replay, verification challenge, and subject authorization before enablement.    |

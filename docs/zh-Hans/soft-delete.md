# 软删除策略

本文回答一个问题:调用 XID 的 DELETE 接口后,数据到底发生了什么,还能不能恢复。读者是接入 Management API 的集成者,以及要新增可删除资源的贡献者。

原则:身份、授权和审计相关资源一律软删除,普通读路径过滤掉;只有一次性凭据材料和有保留期的聚合事实才物理删除。物理删除的完整清单在本文末尾"Hard delete 例外"。

## 资源删除语义

## 查询过滤规则

- 普通用户、普通组织、account portal、platform console、Management API、RBAC token metadata helper 默认不返回或统计 `deleted_at IS NOT NULL`、`revoked_at IS NOT NULL` 或 `status = deleted` 的资源。
- Management API `POST /v1/users` 和 `PATCH /v1/users/:id` 的 `username`、`external_id` 查重只匹配 active non-deleted 用户。D1 唯一索引 `users_tenant_username_unq`、`users_tenant_external_id_unq` 是 active-only partial unique index,soft deleted 用户不再占用这两个 identifier。
- 所有会签发 cookie session 的认证入口经 `issueSession` 统一检查关联 user active 且 `deleted_at IS NULL`,覆盖 password、Magic Link、OTP、passwordless、passkey、social OAuth、SAML/SSO、password reset 自动登录。
- 平台管理端需要查看 deleted 或 revoked 资源时,必须走 platform 管理接口,并通过 `instance_manager` 门控。
- 租户隔离条件必须仍由 `createTenantDb` 注入,软删除过滤只能追加收窄条件,不能替代 `tenant_id` 条件。
- `TenantScoped` 不暴露通用 `delete`,物理删除只能显式调用 `hardDelete`。业务资源删除默认使用状态字段或时间戳字段。
- 每个 restore 端点都配跨租户越权测试:跨租户 restore 返回 404 且不修改受害租户行,secrets 不回显,users restore 遇到 active identifier 冲突返回 409,membership restore 拒绝 deleted user。测试在 `apps/server/worker/v1/__tests__/isolation.test.ts`。

## Hard delete 例外

| 资源                           | 调用点                                                                                                                      | 原因                                                                                      | 边界                                                               |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| verification tokens            | `auth/otp.ts`、`auth/magic-link.ts`、`me-auth/email-verify-token.ts`、`me-auth/passwordless.ts`、`me-auth/mfa-challenge.ts` | 一次性认证 token,验证成功、过期或失败次数到上限后不能保留可重放材料                       | 只按当前 tenant 查询层和 token purpose 删除                        |
| password reset tokens          | `me-auth/password-reset.ts`                                                                                                 | 密码重置 token 是一次性机密材料,创建新 token 前作废旧 token,验证后立即失效                | 只按当前 tenant 查询层和 token hash 删除                           |
| backup codes                   | `auth/backup-codes.ts`                                                                                                      | 重新生成恢复码会作废旧批次;恢复码不作为审计资源保留,审计事件另写                          | 只按当前 tenant 查询层和 user id 删除                              |
| SCIM group members             | `scim/groups.ts`、`scim/shared.ts`                                                                                          | membership join table 表达当前组成员集合,组删除或 PATCH replace/remove 时需要同步当前集合 | group 与 directory user 仍由 soft delete 和 tenant-scoped 查询保护 |
| SCIM pending members           | `scim/users.ts`、`scim/shared.ts`                                                                                           | unknown member 占位只用于 SCIM 幂等补偿,成员解析成功或组成员重算后应清理                  | 只清理当前 tenant 下对应 group/ref 占位                            |
| expired sessions               | `crons/hourly.ts` `hardDeleteExpiredSessions`                                                                               | session 表有保留期,过期行不再参与认证、撤销或恢复                                         | 只删除 `expires_at IS NOT NULL AND expires_at < now`               |
| monthly usage retention        | `crons/daily.ts` `hardDeleteOldMonthlyUsage`                                                                                | 聚合计量事实只保留 13 个月窗口,超期不作为身份审计资源                                     | 只删除 `year_month < cutoff` 的 `usage_monthly` 行                 |
| Durable Object transient state | `durable-objects/*`                                                                                                         | OAuth state、PAR、device flow、challenge、rate limit 和 metering set 是短期协调状态       | 不作为 D1 业务资源恢复入口                                         |

## Migration 规则

- 只新增 migration,不改写旧 baseline。
- 新增软删除字段使用 `revoked_at` 或 `deleted_at`,类型为 Unix 毫秒 timestamp。
- 增加字段后同步 schema、路由过滤、写接口和测试。

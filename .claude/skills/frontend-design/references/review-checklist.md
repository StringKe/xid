# Design review checklist

The scored review for the frontend-design skill. Run it on Paper artboards before code and on the
running surface before handoff. The reviewer is never the agent that generated the surface
(https://www.anthropic.com/engineering/harness-design-long-running-apps).

## Scoring

- Hard gates (H): any FAIL blocks delivery and is fixed immediately.
- General items: count FAILs. 0-1 passes; 2-3 means replace each failing element; 4 or more means
  rework the surface. The thresholds follow
  https://github.com/hungv47/meta-skills/blob/main/skills/marketing/create-brand/references/ai-slop-detection.md
  and match Adrian Krebs' grading of 1590 Show HN pages, where 4+ patterns is heavy
  (https://www.developersdigest.tech/blog/ai-design-slop-and-how-to-spot-it).
- An item kept on purpose is recorded with its reason and code location as "kept on purpose" and does
  not count as a FAIL (practice from
  https://github.com/RachidChabane/cca-f-exam-trainer/blob/main/AI-UI-AUDIT-CHECKLIST.md).
- Surface column: S = Site, H = Hosted Auth and account portal, C = Console. An item that does not
  apply is SKIP.

## Tools

- Paper artboards: `get_screenshot` for the whole; `get_computed_styles` for `border-radius`,
  `box-shadow`, `color`, `font-family`; `get_tree_summary` / `get_children` for structure;
  `find_nodes` for text; `get_jsx` for literal values in exported code.
- Running pages: DevTools Computed and Rendering panels (emulate `prefers-reduced-motion` and dark),
  `getComputedStyle` scans in the console; `npx impeccable detect` (deterministic rules,
  https://github.com/pbakaus/impeccable); AI Design Checker (`node check.js <url>`, 15 deterministic
  patterns, about 5-10% false positives on manual sampling,
  https://github.com/AdrianKrebs/ai-design-checker/blob/main/README.md); repository gates
  `pnpm run i18n:audit`, `pnpm run protocols:source-map`, `pnpm run check`.
- Screenshots: 1440 and 390 wide, light and dark, one per state (empty, loading, error, long text),
  captured serially in the user's Chrome via browser-use.

## Four-criterion assessment

Beyond the item scores, the reviewer writes one paragraph per criterion. The first two weigh more;
models already do reasonably on the last two
(https://www.anthropic.com/engineering/harness-design-long-running-apps).

- Design quality: color, type, layout and imagery form one mood and identity, not assembled parts.
- Originality: evidence of deliberate decisions; template layouts, library defaults and AI patterns
  fail here.
- Craft: type hierarchy, spacing consistency, color harmony, contrast.
- Functionality: a user understands the purpose, finds the primary action and completes the task
  without guessing.

Spoken cross-check (https://developers.openai.com/blog/designing-delightful-frontends-with-gpt-5-4):
Is the brand recognizable at a glance on the first screen? Is there one clear visual anchor? Do the
headings alone explain the page? Does each section do one job? Are these cards necessary? Does the
motion reinforce hierarchy or atmosphere? Does it still look finished without decorative shadows?

## Calibrating the reviewer

Read review records, find where the reviewer disagreed with human judgment, and adjust the review
prompt (https://www.anthropic.com/engineering/harness-design-long-running-apps).
